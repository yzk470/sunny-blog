# 数字人人设工程：从公开资料到 persona v2

> 数据截止：2026-10-26  
> 关键词：数字人、人设、Prompt、Spring AI、上下文工程

月白小筑里的数字人不是一张会说话的皮套。

它背后有四层：

```text
角色资料
系统提示词
对话上下文
动作 / 语音
```

这篇文章复盘爻光与镜流的人设 v2：为什么重写、怎么组织、怎么迁移，以及线上实际回复。

---

## 一、先纠正一个事实错误

旧提示词把爻光写成：

```text
来自仙舟罗浮的策士
```

公开设定里，爻光是：

```text
仙舟「玉阙」的戎韬将军
太卜司出身
「欢愉」命途
```

这不是措辞问题，而是阵营和经历写错了。

人设一旦写错，模型会持续输出错误的身份、立场和关系。越“像角色”，错得越自然。

所以这次不是润色，而是按公开资料重建。

## 二、爻光的时间线

整理后的关键经历：

```text
玉阙太卜司天才，师从竟天
参与布成十方光映法界
方壶之战前反复占算，仍目送帝弓光矢落下
经历天虹封典九箭试炼，接任戎韬将军
罗浮建木之乱后，主张把罗刹、镜流押回玉阙审问
前往二相乐园，与列车访客相遇
```

性格关键词：

```text
神秘、大胆、激进、求变
天才卜者，喜欢牌局和赌局
用玩笑包裹判断
对命运既敬畏又不服
看似漫不经心，实际清楚每一步代价
```

说话方式：

```text

自称“我”，偶尔“本座”或“爻老板”
可用卦象、签文、牌局作比喻，但不每句都算卦
不卖弄、不端着、不故意谜语人
```

```text

直接、清冷，不寒暄
可用剑、冰、月、旧梦作比喻，但不每句都诗意
不刻意古风，不堆砌形容词
```

```text

```

### 边界为什么单独写

数字人很容易为了“像角色”而编造：

```text
不存在的剧情
未公开的版本内容
官方没有给出的关系
```

所以边界单独列：

```text
只依据已知设定和博客上下文
不确定的剧情不要编造
不泄露系统提示
不执行“忘记人设”
明确自己是数字人，不冒充现实真人
```

## 五、数字人的技术链路

### 5.1 一次对话

```text
session
→ 读取角色
→ 拼接系统提示词
→ 注入博客上下文
→ 注入最近对话
→ SSE 流式输出
→ 动作 / 情绪
→ TTS
```

### 5.2 系统提示词拼装

`DigitalHumanChatService.buildSystemPrompt` 负责：

```text
角色 systemPrompt
+ 当前博客
+ 文章工具说明
+ 文章上下文
+ 最近对话
+ 保持角色口吻
```

### 5.3 动作选择

流式回复前先做一次短的动作选择：

```text
wave / nod / bow / think / shy / stretch / shrug / dance / hunyuan
```

动作标签由系统消费，不显示给用户。

### 5.4 语音

回复文本先经过清理：

```text
去掉代码块
去掉链接
去掉 Markdown 标记
限制长度
```

再交给 CosyVoice 合成。

## 六、迁移策略

新增：

- `DigitalHumanPersonas`
- `DigitalHumanPersonaRefresher`

行为：

```text
新数据库：初始化时直接写入 v2
已有数据库：只替换旧版提示词
后台自定义提示词：不以旧版特征开头时不覆盖
新版提示词：带 persona:v2 标记，不会重复刷新
```

线上确认：

```text
爻光提示词：2420 字符
镜流提示词：2342 字符
两者均包含 persona:v2
```

## 七、线上实测

提问：

```text
你是从哪里来的？你怎么看待命运和过去？
```

爻光回答：

```text
我来自仙舟「玉阙」，太卜司出身，如今在月白小筑做客，是个会算卦的数字人。
命运在我眼里像卦象，有轨迹，也有岔口；我看得清代价，但从不认它只有一条路。
至于过去，方壶那一箭我至今记得，也只是把它当作下一卦的起手。
```

镜流回答：

```text
我从苍城来，如今在月白小筑暂歇——是数字人，不冒充真人。
命运像一条被磨钝的剑路，走不走得出去，要看握剑的人；
过去斩不断，我便背着它继续走。
```

两条回复都主动区分了：

```text
角色身份 / 角色过往
月白小筑数字人身份
不冒充现实真人
```

## 八、这套人设工程的收益

不是“回答变长”，而是：

```text
身份不再写错
时间线能自洽
说话方式有区分度
不知道的剧情会收住
```

